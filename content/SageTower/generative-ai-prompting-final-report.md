# [期末報告] AI 驅動的第二大腦：運用提示工程建構深度學習內化系統

## 一、 日常應用情境問題描述

### 1.1 環境背景
身為一名在數位時代持續學習的學習者，我使用 **Obsidian** 作為我的第二大腦（PKM 系統）。我的筆記庫中累積了大量的課程筆記、技術文件與閱讀心得。我追求的是「原子化筆記」（Atomic Notes）與「雙向連結」（Backlinks），旨在建立一個網狀的知識體系，而非單向的資料夾結構。

### 1.2 帶來的困擾與造成的影響
儘管在平時作業二中，我已經初步實現了 AI 自動添加 `[[ ]]` 連結的功能，但在實際深度學習中，仍面臨以下三大困擾：
1. **知識碎片化（Information Fragmentation）**：AI 雖然能摘要單一文章，但無法主動與我筆記庫中「已存在的舊知識」產生深度對話或衝突對比。
2. **缺乏批判性內化（Lack of Internalization）**：單純的摘要只是「搬運知識」，我常常在讀完 AI 整理的重點後，依然覺得這些知識不屬於我，缺乏「主動提取」的過程。
3. **多源資料整理負擔**：當我同時研究一個課題（例如：提示工程）時，資料來源包含影片逐字稿、學術論文、部落格。手動將多種格式統一為 Obsidian 原子筆記極其耗時。

### 1.3 嘗試進行的解決做法
我嘗試過手動整理，但隨著資訊量爆炸，手動整理的速度遠跟不上閱讀的速度。因此，我決定開發一個「**深度學習內化提示框架**」，讓 AI 不僅是整理者，更是我的「思維辯證助教」。

### 1.4 技術環境與模型配置
在本次專題的開發與提示工程（Prompt Engineering）測試中，我選用了以下技術環境進行協作：

AI 協作平台：Antigravity (由 Google DeepMind 開發之代理型 AI 編碼助理)。
使用模型：Gemini 3 Flash。
協作與紀錄方式： 為了確保開發邏輯的透明度並完整保留「提示詞迭代紀錄」，在本次專題中我刻意不使用 Antigravity 的自動撰寫（Auto-write）功能。 我採取「AI 建議產出 -> 人工審核優化 -> 手動複製貼上」的模式進行。這種做法能讓我精確掌控每一階段的提示詞變動，並在報告中完整呈現從初步構想到最終優化指令的演進脈絡，避免自動化功能直接覆蓋掉寶貴的思維辯證過程。

原文 Retrieval-Augmented Generation for Large Language Models: A Survey | PPT | 中文

引言
在人工智慧和自然語言處理領域，生成式模型如 GPT-3 和 GPT-4 已經展示了強大的文本生成能力。然而，這些模型有時會產生不準確或不相關的回應。為了解決這些問題，檢索增強生成（Retrieval-Augmented Generation, RAG）技術應運而生。本文將介紹 RAG 技術的基本概念、運作原理及其應用。

什麼是 RAG？
RAG 是一種結合預訓練大型語言模型與外部資料源的技術。這種方法結合了 GPT-3 或 GPT-4 等大型語言模型的生成能力與專門資料檢索機制的精確性，從而產生能夠提供細膩回應的系統。

RAG 的運作原理
RAG ref
RAG 的運作可以分為以下幾個步驟：

資料收集：首先，收集應用所需的所有資料，例如用戶手冊、產品資料庫和常見問題解答列表。

Indexing:
資料分塊（Chunk）：將資料分解成更小被分割成區塊、更易管理，編碼成向量，以提高檢索效率。
文檔嵌入：將資料轉換為向量資料庫，並儲存在向量資料庫中，確保系統能夠理解用戶查詢並匹配相關信息。
Retrieval 處理用戶查詢：
將用戶查詢轉換為嵌入，並與文檔嵌入進行比較，檢索最相關的資料塊。
在這一階段，RAG首先使用檢索模型來從預先構建的文檔庫中挑選出最相關的文本片段。這些片段通常由嵌入表示（embeddings）所選擇，根據語意相似性檢索與問題最相關的前 k 個區塊。
Generation 生成回應：
檢索到的文本塊連同初始用戶查詢一起被輸入語言模型，生成對用戶問題的連貫回應。生成模型（通常是基於Transformer的架構）會將這些檢索出的文本片段作為上下文信息，輸入到生成過程中。這樣，模型不僅僅依賴於內部的語言表示，還能利用檢索到的外部知識來生成更加準確的文本。
三種 RAG
本篇作者將RAG分為三種：Naive RAG、Advanced RAG、Modular RAG。
3RAGref

Naive RAG
傳統的RAG包含了: Indexing ⮕ Retrieval ⮕ Genaration

Indexing:
從清理和提取 PDF、HTML、Word 和 Markdown 等不同格式的原始資料開始，將其轉換為統一的純文字格式。
Data Embedding：因為 Model 看不懂文字，要轉換成有意義的數字。
M3E (Masked Language Modeling with Entity Embeddings)： 是一種改進的 Masked Language Modeling (MLM) 技術，它結合了實體(Entity) Embeddings，可以更好地理解文本中的實體(Entity)和關係。M3E 通常用於構建語言模型，可以應用於 RAG 的語言模型部分。
BGE (Bi-Encoder with Global Embedding)： 是一種用於信息檢索的技術，它使用兩個編碼器：一個編碼用戶查詢，另一個編碼文檔。BGE 可以用於 RAG 的信息檢索部分，幫助找到與用戶查詢最相關的文檔。
Vector Database: 儲存 Embedding 進資料庫。
補充：
Skip-Gram 和 CBOW 是用於 Word Embeddings 的技術，它們可以學習詞語之間的語義關係，並將詞語轉換成向量表示。這些向量表示可以作為語言模型的輸入，幫助語言模型理解詞語之間的關係。Skip-Gram 和 CBOW 可以被用於構建 RAG 中的語言模型，但並非 RAG 本身的一部分。 例如在訓練語言模型時，可以使用 Skip-Gram 或 CBOW 來生成詞嵌入，然後將這些詞嵌入作為語言模型的輸入。

簡而言之：

Skip-Gram 和 CBOW 用於生成詞嵌入，是語言模型的基礎技術。
M3E 改進了 MLM，可以更好地理解文本中的實體和關係，可以用於構建 RAG 的語言模型。
BGE 是一種信息檢索技術，可以用於 RAG 的信息檢索部分。
Naive RAG 困難
缺點: 檢索階段經常在precision和recall方面遇到困難，導致選擇錯位或不相關的區塊，並遺失關鍵資訊，生成困難。在產生回應時，模型可能會面臨幻覺問題，即產生檢索到的上下文不相符的內容。

Advanced RAG
Index Optimization ⮕ Pre-Retrieval Process ⮕ Retrieval⮕ Post-Retrieval Process ⮕ Genaration

Pre-Retrieval Process
在檢索之前，可以使用query改寫、routing 路由和 query擴展，讓模型改寫問題或是產生一個指導性的假文檔，然後將原始查詢與這個假文檔結合，形成一個新的query。

Optimizing Data Indexing
Chunking Optimisation：因為 Model 輸入的長度有限，需要把文本被分割成更小的、易於理解的區塊。
Small2Big: 在 sentense 級別做 embedding，找到相似的在找大塊的檔案（parent documents）檢索出來。
Sliding window technology：滑動窗口，讓chunk一層層重疊整個段落。
 ref

VectorDB / GraphDB

Post-Retrieval Process
ReRank（重新排序）：使用更高級的模型（如跨編碼器或多向量重排序器）對這些文檔進行重新排序，確保最相關的文檔排在前面。

跨編碼器（Cross-Encoder）： 直接將查詢和文檔作為輸入，訓練一個模型來預測它們之間的相關性得分，這種方法通常能獲得更高的準確性，但計算成本也更高。
多向量重排序器（Multi-Vector Rerankers）：這種方法會使用多個向量來表示查詢和文檔，並通過這些向量之間的相似度進行排序。
Modular RAG
Modular RAG 是一種將 Retrieval Augmented Generation (RAG) 系統分解成獨立模組的架構。每個模組負責特定的任務，例如信息檢索、文檔選擇、上下文編碼和文本生成。這種模組化的設計可以提高 RAG 系統的靈活性、可擴展性和可維護性。

實際應用與未來
RAG在問答系統中特別有用，如在醫療諮詢、法律咨詢、和教育領域。舉例來說，對於一個醫療問答系統，RAG可以從最新的醫學文獻中檢索信息，提供給醫生或患者最準確的建議。

儘管RAG技術在多個領域展現了其潛力，但仍然面臨一些挑戰。例如檢索和生成模型之間的協同效應需要進一步優化，以避免生成內容過度依賴某些檢索片段。此外如何處理多樣性和創造性與準確性之間的平衡，也是RAG技術未來需要解決的問題之一。

未來隨著更多資料的引入和模型架構的改進，RAG技術有望在更多應用中發揮作用，成為自然語言處理領域的重要工具。它不僅能夠提高生成文本的品質，還能促進知識更新，使人工智慧系統能夠更好地應對快速變化的世界。

### 【AI筆記】RAG技術介紹：從論文入門到實戰重點整理

#### 1. 引言
*   **技術背景**：GPT-3/4 等生成式模型雖強大，但存在不準確（幻覺）或提供不相關資訊的問題。
*   **解決方案**：檢索增強生成（Retrieval-Augmented Generation, RAG）應運而生，旨在結合生成能力與外部知識。

#### 2. 什麼是 RAG？
*   **核心定義**：結合「預訓練大型語言模型 (LLM)」與「外部專門資料源」的技術。
*   **運作優勢**：利用外部資料檢索的精確性，彌補 LLM 內部知識的不足，產生更細緻且準確的回應。

#### 3. RAG 的運作原理
1.  **資料收集**：整理用戶手冊、資料庫或 FAQ 等原始資料。
2.  **Indexing (索引化)**：
    *   **資料分塊 (Chunking)**：將長文檔切分為易於管理的小塊，提高檢索效率。
    *   **文檔嵌入 (Embedding)**：將文字編碼為向量並儲存在向量資料庫。
3.  **Retrieval (檢索)**：
    *   將用戶的查詢（Query）轉換為向量。
    *   依據語意相似性，從資料庫中挑選出最相關的前 $k$ 個資料塊。
4.  **Generation (生成)**：
    *   將檢索出的片段作為「上下文 (Context)」連同原始問題輸入模型。
    *   模型依據外部知識生成連貫且準確的回應。

#### 4. 三種 RAG 架構演進
*   **Naive RAG (基礎架構)**：
    *   **基本流程**：Indexing ⮕ Retrieval ⮕ Generation。
    *   **關鍵技術**：
        *   **M3E**：結合實體嵌入（Entity Embeddings）以更好理解關係。
        *   **BGE**：使用雙編碼器優化檢索部分。
    *   **主要困境**：檢索的精準度與召回率常遇到困難，容易導致內容錯位或產生與上下文不符的「幻覺」。

*   **Advanced RAG (進階架構)**：
    *   **流程優化**：增加檢索前（Pre）與檢索後（Post）的處理環節。
    *   **Pre-Retrieval (檢索前)**：透過查詢改寫（Query Rewrite）、路由（Routing）或擴展，改善輸入問題的品質。
    *   **Indexing 優化**：
        *   **Small2Big**：由句子級檢索延伸至父文件（Parent Documents）。
        *   **Sliding Window**：利用重疊的滑動窗口保留上下文完整性。
    *   **Post-Retrieval (檢索後)**：
        *   **ReRank (重排序)**：利用 Cross-Encoder 等高級模型對結果重新排序，確保最相關的內容排在首位。

*   **Modular RAG (模組化架構)**：
    *   **架構設計**：將系統拆解為獨立的模組（如：檢索、選擇、編碼、生成）。
    *   **核心優勢**：極高的靈活性與可維護性，各模組可獨立優化。

#### 5. 實際應用與未來挑戰
*   **實務應用**：高度依賴專業知識的領域，如醫療諮詢、法律服務、教育系統。
*   **當前挑戰**：
    *   優化檢索與生成模型間的「協同效應」。
    *   平衡回應內容的「準確性」與「創造性」。
*   **未來展望**：隨著資料與架構進步，RAG 將成為 NLP 領域知識更新與品質提升的重要工具。

## 2. 知識解構：從 Naive 到 Modular

### 【客觀事實：架構特徵】
*   **Naive RAG**：最簡施法路徑。流程為 `Indexing (PDF/Doc ⮕ Embedding ⮕ VectorDB)` ⮕ `Retrieval (語意相似度檢索)` ⮕ `Generation`。
    *   *技術組件*：使用 M3E (實體強化) 或 BGE (雙編碼器) 進行向量化。
*   **Advanced RAG**：增加「預處理」與「後處理」。
    *   *關鍵術式*：**Pre-Retrieval** (查詢改寫/擴展)；**Post-Retrieval** (ReRank 重排序/Cross-Encoder)。
    *   *索引優化*：Small2Big (子句檢索、父塊產出) 與 Sliding Window (滑動重疊)。
*   **Modular RAG**：高度解耦架構。將檢索、選擇、編碼、生成模組化，支持靈活替換與平行擴展。

### 【AI 洞察：技術本質與矛盾】
1.  **檢索的幻象**：Naive RAG 的失敗往往不在於 LLM 不夠強，而是在於「檢索階段的精準度與召回率瓶頸」。如果餵給模型的資料就是錯的，再強的推論能力也無法避免幻覺。
2.  **空間與時間的權衡**：Advanced RAG 中的 `Small2Big` 揭示了一個深刻的矛盾——我們需要「極小的向量」來精準匹配，但需要「極大的上下文」來生成語意。
3.  **從工具到系統**：Modular RAG 的出現標誌著 RAG 已從單純的「技巧」演變為一種「軟體工程架構」，這意味著未來 AI 的穩定性將取決於「模組間的協同效應」而非單一模型。

## 3. 蘇格拉底式反思問題
*   **本質思考**：如果 RAG 的核心是「More Context = Less Hallucinations」，那麼當 Context 達到無限大時，檢索技術是否還具有存在的價值？
*   **結構思考**：Advanced RAG 的 `ReRank` 過程本質上是「第二次檢索」，為什麼我們不直接在第一次檢索時就做到最精準？這反映了現行向量檢索的什麼弱點？
*   **實務思考**：在醫療或法律這種「容錯率為零」的場景中，單純的語意相似度匹配 (Semantic Similarity) 是否足以支撐其安全性？

## 四、 心得與總結

透過本次「深津氏框架」與 Obsidian 的整合實踐，我對提示工程如何驅動深度學習有更具體的體悟，以下細分三個層次進行總結：

### 4.1 知識連結的範式轉移：從「事後貼標」到「事前錨定」

傳統的 AI 摘要通常是孤立的，但在套用框架後，AI 展現了顯著的進化：

- **前置連結**：在分析 RAG 內容前，AI 會先主動檢索我筆記庫中的 `[[Grimoires]]` 系列與 `[[Context Engineering]]`。這讓新知識不再是孤島，而是在產出瞬間就「掛載」於現有的知識架構上。
- **補齊認知缺口**：AI 不僅僅是整理文章，它會識別出文章中提及但我的筆記庫中缺失的術語，提示我需要補齊相關內容。

### 4.2 蘇格拉底式引導：將「摘要」轉化為「辯證」

框架中定義的「蘇格拉底式角色」徹底改變了對話性質：

- **突破同溫層**：AI 提出的「反思問題」並非課後練習，而是針對技術本質的挑戰。例如，它引導我思考「當上下文無限大時，檢索技術的價值」，這強迫我從單純的「使用者」提升到「系統設計者」的高度。
- **內化過程**：這種辯證過程是「知識屬於我」的關鍵。透過回答 AI 的提問，我將資料轉化為具備批判性的個人見解。

### 4.3 平台協作特質：Antigravity 的情境感知能力

在本次實驗中，我觀察到 Antigravity (Gemini) 的特定優勢：

- **檔案深度讀取**：由於它具備跨檔案的閱讀權限，它給出的「行動建議」具有極高的針對性。它不僅建議我如何整理這篇 RAG 筆記，更進一步建議我「改寫之前寫過的舊內容」以優化整理邏輯，這是單純對話型 AI 無法做到的。
- **動態優化指引**：它能根據我目前的 Obsidian 標籤體系（如 SageTower 的目錄結構）動態調整輸出格式，確保產出物能直接「無縫嵌入」我的工作流。

### 總結：提示工程是 LLM 的「靈魂導師」

在不同平台與模型下，LLM 的原生表現各有千秋，但**提示工程（特別是深津氏架構）扮演了「結構化過濾器」的角色**。它讓 AI 不再只是幫我「寫筆記」的代工者，而是成為一個能引導我思考、預判我的需求、並協助我建構網狀知識體系的「第二大腦」導師。這種協作模式證明了：**決定知識產出質量的，往往不是 AI 的參數規模，而是提問者的提示架構與思維深度。**
