# 📝 術式藍本完整指南：從入門到實戰

> 在學會吟唱第一個咒語之前，你其實可以先學會「思考法術」。術式藍本（虛擬碼）就是這座橋梁。

---

## 前言：為何需要術式藍本？

你有沒有遇過這種情況：腦袋裡明明有解題思路，卻不知道如何下筆寫咒語？或者開了一個新法術，結果寫了一半才發現邏輯根本不對？

**術式藍本（Pseudocode，虛擬碼）** 就是用來解決這個問題的工具。

它不是真正的咒語，沒有嚴格的語法限制，卻能完整表達法術的流程與邏輯。無論你是初入奧術殿堂的新手，還是身經百戰的資深 Oracle，術式藍本都是一個值得掌握的思考工具。

---

## 一、什麼是術式藍本？

術式藍本是一種**非正式的、高層次的法術描述方式**，結合了自然語言與咒語結構的特點，但不受任何特定語法限制。

它的核心目的只有一個：**清楚表達「要做什麼」，而不糾結「怎麼詠唱」。**

舉個例子，描述「精神藥劑釀造」的術式藍本長這樣：

```text
開始
  漂浮魔法 //拉取咖啡豆
  碾碎魔法 //磨製豆粉
  混合魔法 //調和水粉比例
  加熱魔法 //煮沸泉水
  灌注熱水 //萃取精華
  等待滴濾完成
  將黑色魔藥倒入杯中
  （可選）添加糖與牛奶中和苦味
結束
```

簡單明瞭，對吧？這就是術式藍本的精髓。

---

## 二、術式藍本的優劣

### ✅ 優勢

| 優勢       | 說明                                               |     |
| -------- | ------------------------------------------------ | --- |
| **易於理解** | 接近自然語言，非奧術修行者也能讀懂，有助於需求溝通                        |     |
| **通用性高** | 不依賴特定咒語體系，可輕鬆轉換成 精靈、魔族、哥布林、龍族(Python、Java、C++) 等 |     |
| **專注邏輯** | 讓奧術專家集中在法術設計，不被語法細節干擾                            |     |
| **促進協作** | 施法者、奧法專家、奧術學員都能理解，降低溝通成本                         |     |
| **便於記錄** | 清晰紀錄法術思路，是奧法卷軸的好幫手                               |     |

### ❌ 劣勢

- **缺乏標準化**：不同人的寫法可能差異很大，偶爾造成歧義。
- **無法直接執行**：最終仍需轉換為實際咒語。
- **可能過度簡化**：省略太多細節，轉換時才發現問題。

## 三、四大基礎術式

術式藍本的骨架由以下四種結構組成，掌握了它們，就能描述任何法術。

### 1. 順序術式（Sequence）

法術從上到下，逐行施展。這是最基本的結構，上面的「精神藥劑釀造」就是一個純粹的順序術式範例。

---

### 2. 選擇術式（Selection）

根據條件決定施展哪段術式。常見形式有三種：

**① IF-THEN（單向占卜）**
```text
如果 魔力濃度 > 閾值 那麼
  顯現 "魔力已滿！"
結束如果
```

**② IF-THEN-ELSE（雙向占卜）**
```text
如果 修行評分 >= 60 那麼
  顯現 "試煉通過"
否則
  顯現 "試煉失敗"
結束如果
```

**③ ELSE IF（多重占卜）**
```text
如果 貢獻度 >= 90 那麼
  顯現 "S 級冒險者"
否則 如果 貢獻度 >= 80 那麼
  顯現 "A 級冒險者"
否則 如果 貢獻度 >= 70 那麼
  顯現 "B 級冒險者"
否則 如果 貢獻度 >= 60 那麼
  顯現 "C 級冒險者"
否則
  顯現 "初心者"
結束如果
```

**④ CASE / SWITCH（屬性判定）**

當一個變數有多種可能值時，CASE 結構比連續 IF-ELSE 更清楚：

```text
選擇 屬性 之中的情況：
  情況 "火焰":
    顯現 "選擇了火焰屬性"
  情況 "冰霜":
    顯現 "選擇了冰霜屬性"
  情況 "雷電":
    顯現 "選擇了雷電屬性"
  預設情況:
    顯現 "未知屬性"
結束選擇
```

---

### 3. 循環術式（Iteration）

重複施展某段術式，直到條件不滿足為止。

**① WHILE-DO（先占卜、再施展）**

適合「不確定要迴響幾次」的情境：

```text
// 計算魔力累積總量
宣告 計數器 為 整數 ＝ 1
宣告 魔力總量 為 整數 ＝ 0

當 計數器 <= 法力節點數 時執行：
  設定 魔力總量 ＝ 魔力總量 + 計數器
  設定 計數器 ＝ 計數器 + 1
結束當

顯現 "魔力累積總量為：" + 魔力總量
```

**② FOR-DO（已知次數時使用）**

適合「確定要迴響幾次」的情境：

```text
// 找出 1 到 10 中的雙數符文
對於 序號 從 1 到 10 執行：
  如果 (序號 除以 2 的餘數) == 0 那麼
    顯現 序號
  結束如果
結束對於
```

**③ REPEAT-UNTIL（先施展、再占卜）**

和 WHILE 不同，**至少會執行一次**，適合感應法器這類場景：

```text
// 猜法器編號，直到猜對為止
宣告 神秘法器 為 整數 = 7

重複：
  感應 "請猜測法器編號 (1-10): ", 猜測
  如果 猜測 < 神秘法器 那麼
    顯現 "太低了！"
  否則 如果 猜測 > 神秘法器 那麼
    顯現 "太高了！"
  結束如果
直到 猜測 == 神秘法器

顯現 "恭喜你，正確感應到法器！"
```

---

### 4. 召喚與顯現（Input / Output）

用於表示法術接收外界資訊或呈現結果：

| 關鍵字 | 用途 |
|--------|------|
| `感應` / `INPUT` | 從外界召喚資料 |
| `顯現` / `PRINT` | 將結果展現給世界 |

## 四、術式書寫守則

撰寫術式藍本沒有標準答案，但以下原則能讓你的術式更專業易讀：

1. **保持簡潔**：不需要寫分號或括號，專注表達「邏輯步驟」。
2. **縮排一致**：用縮排清楚表達術式區塊的層次感。
3. **語言一致性**：統一關鍵字，例如統一用「設定」，不要混用「令」、「使」。
4. **適度抽象**：描述「要做什麼」，而非「魔力在底層如何流動」。

## 五、修行試煉

光看不夠，動手才有感。以下三題由易到難，讓你練習把想法轉成術式藍本。

### 試煉一：辨識魔力屬性

```text
開始
  顯現 "請輸入魔力數值："
  感應 魔力值
  如果 (魔力值 除以 2 的餘數) == 0 那麼
    顯現 魔力值 + " 是陰性魔力。"
  否則
    顯現 魔力值 + " 是陽性魔力。"
  結束如果
結束
```

### 試煉二：計算符文序列總和

```text
開始
  宣告 符文序列[5] 為 整數
  設定 符文序列 = [10, 20, 30, 40, 50]
  宣告 累積總量 為 整數 = 0

  對於 i 從 0 到 4 執行：
    設定 累積總量 = 累積總量 + 符文序列[i]
  結束對於

  顯現 "符文序列的總能量為：" + 累積總量
結束
```

### 試煉三：找出最強符文

```text
開始
  感應 "請輸入符文數量：", n
  對於 i 從 0 到 n - 1 執行：
    感應 符文強度[i]
  結束對於

  如果 n == 0 那麼
    顯現 "沒有符文，無從比較。"
  否則
    設定 最強符文 = 符文強度[0]
    對於 i 從 1 到 n - 1 執行：
      如果 符文強度[i] > 最強符文 那麼
        設定 最強符文 = 符文強度[i]
      結束如果
    結束對於
    顯現 "符文中最強數值為：" + 最強符文
  結束如果
結束
```

## 六、進階奧術：強化你的術式

掌握基礎之後，以下幾個進階概念能讓你的術式更接近真實咒語。

### 1. 結界防護（Error Handling）

使用 `TRY-CATCH` 結構來描述異常情況的處理邏輯：

```text
嘗試：
  開啟卷軸 "上古紀錄.txt" 供閱讀
  從卷軸讀取 內容
  關閉卷軸
  顯現 "卷軸讀取成功。"
捕捉 錯誤 作為 e
  顯現 "讀取卷軸時發生錯誤：" + e.訊息
最終：
  如果 卷軸已開啟 那麼
    關閉卷軸
  結束如果
結束嘗試
```

---

### 2. 自我迴響（Recursion）

術式在自身定義中呼喚自己。最經典的範例是計算魔力階乘：

```text
咒式 計算魔力階乘(n 為 整數) 回饋 整數
  如果 n < 0 那麼
    回饋 -1        // 錯誤：負數無階乘
  否則 如果 n == 0 那麼
    回饋 1         // 基礎情況：0! = 1
  否則
    回饋 n * 計算魔力階乘(n - 1)  // 自我迴響
  結束如果
結束咒式
```

自我迴響的關鍵在於兩點：**基礎情況（停止條件）** 和 **迴響呼叫（縮小問題規模）**，缺一不可。

---

### 3. 術式模組化（咒式與儀式）

將重複使用的邏輯封裝起來，提高可讀性與可維護性：

- **咒式（Function）**：執行任務並**回饋數值**。
- **儀式（Procedure）**：執行任務但**不回饋數值**。

```text
咒式 計算結界面積(長度 為 浮點數, 寬度 為 浮點數) 回饋 浮點數
  如果 長度 <= 0 或 寬度 <= 0 那麼
    回饋 -1.0  // 表示輸入無效
  否則
    回饋 長度 * 寬度
  結束如果
結束咒式
```

## 七、經典法術：二分搜尋術

術式藍本最適合用來描述法術邏輯，這裡以「二分搜尋術」為例，展示如何在已排序的典籍中快速找到目標：

```text
咒式 二分搜尋術(典籍目錄, 目標名稱) 回饋 整數
  宣告 左邊界 為 整數 = 0
  宣告 右邊界 為 整數 = 長度(典籍目錄) - 1

  當 左邊界 <= 右邊界 時執行：
    宣告 中間點 = (左邊界 + 右邊界) / 2

    如果 典籍目錄[中間點] == 目標名稱 那麼
      回饋 中間點        // 找到目標
    否則 如果 典籍目錄[中間點] < 目標名稱 那麼
      設定 左邊界 = 中間點 + 1
    否則
      設定 右邊界 = 中間點 - 1
    結束如果
  結束當

  回饋 -1  // 沒有找到
結束咒式
```

二分搜尋術的時間複雜度為 O(log n)，相較於逐一比對的 O(n) 快得多，適合在大型典籍中使用。

## 八、實戰演練：魔能計算器

最後來看一個奧術工程現場的完整範例——**魔力波動資料收集與異常判斷**：

```text
開始
  // 系統設定
  宣告 正常魔力上限 為 浮點數 = 240.0   // 單位：魔能
  宣告 故障閾值 為 整數 = 3               // 連續幾次超標視為故障
  宣告 最大讀取次數 為 整數 = 10

  // 變數初始化
  宣告 讀取計數 為 整數 = 0
  宣告 連續超標計數 為 整數 = 0
  宣告 系統狀態 為 字串 = "正常"

  // 資料收集與判斷
  當 讀取計數 < 最大讀取次數 且 系統狀態 == "正常" 時執行：
    當前讀數 = 生成隨機浮點數(220.0, 260.0)  // 模擬魔能波動
    顯現 "感應到魔能波動: " + 當前讀數 + " ME"

    如果 當前讀數 > 正常魔力上限 那麼
      連續超標計數 = 連續超標計數 + 1
      顯現 "警告：魔能超出正常範圍！"
    否則
      設定 連續超標計數 = 0  // 恢復正常，重置計數
    結束如果

    如果 連續超標計數 >= 故障閾值 那麼
      設定 系統狀態 = "異常"
      顯現 "緊急警報：魔能持續過高，可能發生奧術災難！"
    結束如果

    讀取計數 = 讀取計數 + 1
  結束當

  // 總結報告
  顯現 "--- 計算結束 ---"
  顯現 "共記錄 " + 讀取計數 + " 次魔能讀數"
  顯現 "系統最終狀態：" + 系統狀態
結束
```

這個案例結合了**順序、選擇、循環**三種基礎術式，同時展示了「閾值判斷」這個在魔能運算中非常常見的設計模式。

## 結語

術式藍本不是要取代真正的咒語，而是讓你**先把邏輯想清楚，再動手吟唱**。

從今天開始，在打開 IDE 之前，試著先用術式藍本把你的思路勾勒出來。你會發現，除錯的時間少了，法術結構也清晰得多。

> 好的法術，從好的思考開始。
