# 🧠 提示詞結構化框架：深津式與變數式完全教學

良好的提示詞不該每次從零撰寫。透過「結構化框架」，你可以將提示詞拆解為可重複使用的模板，大幅提升輸出的穩定性與品質。本文將深入介紹兩大主流框架——**深津式**與**變數式**——的發明背景、核心原理與實戰範例。

---

## 一、深津式提示框架（深津式プロンプト）

### 1.1 發明者與背景

深津式提示框架由 **深津貴之（Takayuki Fukatsu）** 所創，他是 note 株式会社的 CXO，也是日本提示工程領域的代表性人物。

2023 年初，ChatGPT 剛普及時，多數使用者僅僅以自然語言隨意提問，輸出品質極不穩定。深津貴之觀察到：**AI 輸出的品質不取決於模型好壞，而是取決於提示詞的結構清晰度**。於是他提出了這套將提示詞「結構化」的框架，迅速在日本社群擴散，成為最廣泛使用的提示詞模板之一。

### 1.2 核心原理：四大元素

深津式框架將提示詞拆解為四個明確區塊：

| 元素 | 日文/英文 | 說明 |
|------|-----------|------|
| **命令** | 命令書 (Instruction) | 定義 AI 角色與任務目標 |
| **制約** | 制約条件 (Constraints) | 限制輸出格式、字數、風格等 |
| **輸入** | 入力文 (Input) | 提供要處理的素材或資料 |
| **輸出** | 出力文 (Output) | 標示輸出區，引導 AI 生成 |

**基本模板：**

```markdown
# 命令書:
あなたは{役割}です。
以下の制約条件と入力文をもとに、最高の{成果物}を出力してください。

# 制約条件:
・{条件1}
・{条件2}

# 入力文:
{入力資料}

# 出力文:
```

### 1.3 六大核心要點

根據課程教材的整理，深津式框架的操作原則可歸納為六點：

1. **清楚定義角色**：賦予 AI 專家身份（如「你是一位資深 Python 工程師」）
2. **明確指示輸入輸出**：規定輸入什麼、獲得什麼
3. **清楚說明輸出內容**：描述輸出應包含的具體要素
4. **使用標記式語言來說明**：利用 Markdown 標籤結構化資訊
5. **以條列式給予指令**：邏輯清晰，降低理解錯誤
6. **限縮 AI 回答範圍**：防止發散，聚焦於核心目標

### 1.4 進化版：深津式 2.0

深津式 2.0 在基本模板的基礎上，加入了「**逆質問**」機制。在輸出區塊後加上一句話：

```
このタスクで最高の結果を出すために、追加の情報が必要な場合は質問をしてください。
```

這讓 AI 在資訊不足時能主動提問，而非盲目猜測，大幅減少因資訊缺口導致的幻覺。

### 1.5 範例一：文章摘要（對照實驗）

**一般提問（無框架）：**

> 幫我摘要這篇文章。

輸出結果往往是隨機的段落提取，格式不固定，缺乏關鍵脈絡。

**深津式框架：**

```markdown
# 命令書:
你是一位專業的知識整理師，擅長萃取文章核心觀點。
請依據以下制約條件與輸入文，輸出最高品質的摘要。

# 制約條件:
・摘要長度不超過 200 字
・必須保留原文中的關鍵數字與數據
・使用條列式呈現三大重點
・末尾附上一句 30 字以內的結論
・若有不明確之處，請先提問再輸出

# 輸入文:
{貼入文章內容}

# 輸出文:
```

**預期效果**：AI 明確知道自己要扮演什麼角色、遵守什麼規則、產出什麼格式，輸出的摘要穩定且可直接使用。

### 1.6 範例二：Python 程式碼生成

```markdown
# 命令書:
你是一位資深 Python 工程師，專精資料處理與效能最佳化。
請依據以下制約條件與輸入需求，輸出可直接執行的程式碼。

# 制約條件:
・遵守 PEP 8 規範
・加入 type hints
・包含完整的錯誤處理（try/except）
・附上函式的使用範例（docstring 中的 Example 區塊）
・輸出格式：單一程式碼區塊，無多餘說明文字

# 輸入文:
需求：撰寫一個函式 `batch_process`，接收一個檔案路徑列表，
讀取每個 CSV 檔案並計算各數值欄位的平均值，
最後回傳一個彙總的 DataFrame。

# 輸出文:
```

**對比一般提問**「幫我寫一段 Python 程式」——AI 可能生成缺乏類型標註、無錯誤處理的程式碼。而深津式框架讓 AI 在一開始就遵循最佳實踐，減少後續修正的迭代次數。

## 二、變數式提示指令

### 2.1 起源與背景

變數式提示指令並非由單一個人發明，而是提示工程社群在實務中自然演化出的通用模式。它的概念來自軟體工程中的「**分離關注點（Separation of Concerns）**」——將固定的邏輯框架與會變動的資料內容分開管理。

在臺灣的大專院校提示工程課程中（如本專案的 `generative-ai-prompting.md`），變數式被正式納入教材，與「直述指令」並列為兩大提示策略。這套方法由於**高複用性**與**輸出穩定**的特性，已成為商用提示詞模板的主流設計模式。

### 2.2 核心原理：邏輯與資料分離

變數式的核心概念是將提示詞分為兩個部分：

| 部分 | 說明 | 範例 |
|------|------|------|
| **固定框架** | 不變的指令結構、任務描述、格式要求 | 「請依據 [目標] 與 [要點] 撰寫文章」 |
| **變數區塊** | 用標記符號標示的可替換內容 | `[目標]`、`[要點]`、`[風格]` |

### 2.3 操作規則

1. **框架與資料分離**：提示詞的邏輯結構固定，僅變數內容隨場景更換
2. **變數用標記標示**：使用 `[ ]`、`{ }` 或 `## [VariableName]` 清楚標示變數位置
3. **結構化管理**：使用 Markdown 標題層級區分不同變數區塊
4. **高複用性**：同一組模板可處理完全不同領域的任務
5. **輸出穩定**：固定的框架確保不同輸入下仍產出統一的格式

---

### 2.4 範例一：感謝郵件模板

```markdown
# 撰寫一份感謝郵件
請依據下列的 [目標] 跟 [要點] 撰寫感謝郵件，
並符合 [文章風格] 的設定

## [目標]
- 成功得到商談機會

## [要點]
- 先提出感謝
- 再提出邀約
- 強調在商談時，可說明最新發展趨勢與潛在商機

## [文章風格]
- 商業信件
- 正式
- 有禮貌
```

**更換變數即可用於不同場景：**

| 場景 | 變更 [目標] | 變更 [要點] | 變更 [風格] |
|------|------------|------------|------------|
| 面試感謝信 | 獲得錄取通知 | 感謝面試官、重申熱情、期待報到 | 正式、謙虛 |
| 客戶跟進信 | 促成第二次會議 | 感謝參與、補充資料、提供優惠 | 積極、專業 |
| 合作邀約信 | 建立合作關係 | 說明價值、提出具體方案、邀請討論 | 誠懇、開放 |

### 2.5 範例二：會議記錄模板

```markdown
## [角色]
你是一位專業行政助理，擅長快速整理會議紀錄並提煉重點。

## [背景]
你剛參加完 [部門名稱] 的 [會議類型]，
會議時間為 [會議日期]，與會人員共 [人數] 位。

## [任務]
撰寫一份清晰的會議紀錄，包含討論重點、決議事項及後續行動計畫。

## [輸出格式]
以條列式呈現，分為三個區塊：
1. **討論內容**：會議中提出的主要議題與觀點
2. **決議事項**：團隊達成的共識與決定
3. **待辦事項**：每項任務需包含負責人與截止日期

## [語氣]
- 正式
- 精煉
- 便於快速閱讀與追蹤進度
```

**實際填入變數後的應用範例：**

```markdown
## [角色]
你是一位專業行政助理，擅長快速整理會議紀錄並提煉重點。

## [背景]
你剛參加完 **研發部** 的 **週進度同步會議**，
會議時間為 **2026/05/20**，與會人員共 **8** 位。

## [任務]
撰寫一份清晰的會議紀錄...

```

## 三、兩者比較

| 比較維度 | 深津式框架 | 變數式指令 |
|---------|-----------|-----------|
| **發明者** | 深津貴之（note CXO） | 社群共創，無單一發明者 |
| **核心思維** | 角色 + 制約 = 高品質輸出 | 框架 + 變數 = 高複用性 |
| **結構標記** | `#命令書`、`#制約条件` | `## [變數名稱]` |
| **最強場景** | 需要嚴格規範的專業任務 | 大量重複但內容變動的任務 |
| **學習曲線** | 中等（需理解 4 元素 + 6 原則） | 低（理解邏輯/資料分離即可） |
| **可組合性** | 可嵌入變數式框架中作為命令書區塊 | 可將深津式角色定義作為變數值 |

**實務建議**：兩者並非互斥——你可以將深津式框架作為「命令書」的結構，並在制約條件中使用變數標記，融合兩者優勢。
