# 🧠 Context Engineering (脈絡工程) 教學指南

在與大型語言模型 (LLM) 互動的過程中，**Context Engineering (脈絡工程)** 扮演著決定性的角色。當我們了解 AI 的本質是「預測下一個 Token (Token Prediction)」時，給予 AI 什麼樣的「前提與背景」，就決定了它預測的方向。

這篇文章將跳脫單純的指令下達，帶領你從底層運作機制的角度，理解如何「設計」上下文，打造出如同專家般的 AI Agent。

---

## 一、理解核心：什麼是上下文 (Context Window)？

我們要有一個根本認知：**LLM 沒有長期記憶，它只有上下文視窗 (Context Window)**。

當你在 ChatGPT 等平台與 AI 進行連貫對話時，你可能會覺得「AI 記得我剛剛說的話」。事實上，這是因為平台在背後替你完成了**動態的脈絡組裝**。

### 1. 對話的產生流程
當你輸入一個新問題，平台並不是只把新問題傳給 LLM。它的實際運作方式如下：
1. **輸入 (Prompt)**：取出你過去的問題與 AI 的回答。
2. **打包 (Pack)**：將 [對話歷史] + [當前問題] 全部接合在一起。
3. **推論 (Inference)**：將這包龐大的文字送給 LLM 重新計算。

**這也就是為什麼：**
- Context Window 的內容與多寡，決定了 LLM 當下的工作能力。
- 一旦對話總長度超過了 Context Window 的限制，最前面的對話（記憶）就會被捨棄，這也就是 AI 開始「忘記」設定的原因。

### 2. Context Window 裡的 Prompt 結構
在完整的 API 呼叫或是平台背後的結構中，這扇「上下文視窗」通常被分為三種角色標籤：
- **`System` (系統提示)**：賦予 AI 規則與人格。例如：「你是一位 Python 專家，並偏好使用條列式回答」。這也是建立 AI 基礎脈絡最穩固的地方。
- **`User` (使用者提示)**：使用者當下提出的問題或指令。
- **`Assistant` (AI 助理)**：LLM 過去產生的回覆紀錄。

這三者的結合，就是讓沒有靈魂的模型轉變為專屬助理的關鍵。

## 二、建構優質脈絡的三大策略

了解運作機制後，我們就可以主動「工程化」我們的脈絡，而不只是被動依賴對話紀錄。

### 策略 1：設計清晰的框架式脈絡 (Framework)
避免讓 AI 自己大海撈針，我們可以透過結構化標記（如 Markdown 或 XML）將資訊切塊，利用變數槽位 (Variables) 區分出資料與指令：

```markdown
# 任務
請依據下列的 [背景資料] 跟 [具體要求] 撰寫回應，並符合 [輸出格式] 的設定。

## [背景資料]
(貼上長篇大論的會議逐字稿或是參考文章)

## [具體要求]
- 整理出三大重點
- 指出潛在的風險

## [輸出格式]
- 必須是繁體中文
- 使用條列式 (Bullet points)
- 末尾附上 50 字摘要結論
```
**分析**：這種結構化脈絡能有效將**靜態脈絡**（格式、角色設定）與**動態脈絡**（會更動的背景資料）分離，大幅提升 AI 抓取重點的成功率與輸出的穩定性。

### 策略 2：善用樣本提示 (Few-Shot Prompting)
與其花費數百字解釋「我希望你的語氣既詼諧又帶點諷刺」，不如直接在 Context 中塞入幾個實際範例。在脈絡中放入**多個「輸入與輸出」的範例 (Few-Shot)** 是穩定複雜任務輸出的不二法門。

- **零樣本 (Zero-Shot)**：只有指令。容易產生偏倚或格式跑版。
- **少樣本 (Few-Shot)**：給予 2~3 個成功執行的案例，能有效引導 LLM 在龐大的潛在空間 (Latent Space) 中，精準降落到你期望的那個點。

### 策略 3：思維的脈絡化 —— 思維鏈 (Chain-of-Thought, CoT)
如果你直接問 AI 一個複雜的邏輯問題，它可能會隨機猜測並胡言亂語（產生幻覺）。我們可以在脈絡中強制要求 AI **先展現思考過程，再給出答案**。

**引導 AI 思考的脈絡範例**：
1. 請先分析問題的關鍵條件有哪幾項。
2. 列舉這些條件下可能發展的情境。
3. 一步步推導其合理性。
4. 最後綜合結果給出唯一解答。

藉由將這段「思考步驟」寫入上下文中，AI 在生成最終答案前，就會產生更豐富有效的自我推導脈絡。

## 三、脈絡管理的進階演進：打破 Context Window 限制

隨著 AI 應用的複雜化，把所有東西都塞進 Context Window 既昂貴又容易導致模型效能下降（大海撈針問題）。現在的解決方案走向了更智慧的分層系統：

### 1. 檢索增強生成 (RAG)
遇到 AI 本身不懂的專有知識（內部企業文件等），我們可以透過 RAG 將相關資料變成「外接記憶庫」。當使用者提問時，系統會先去資料庫撈出最相關的片段（也就是建立短暫而強壯的脈絡），再和使用者的問題結合後送給 LLM。

### 2. 進階的記憶體系與自動整理 (Auto Dream)
新一代的 Agent 已經具有三層記憶機制：
- **短期記憶**：當下的對話歷史。
- **長期記憶**：將使用者的偏好（如：專案代號、設計習慣）固化成文件。
- **記憶壓縮 (Auto Dream)**：在空閒時自動將過長的對話從 32K 壓縮到 7K，提煉出精華摘要，確保每次帶進 Context 的都是最乾淨、最高效的脈絡。

### 3. 從提供脈絡到提供「技能 (SKILL)」
當 AI 被賦予了工具 (Tools/MCP) 後，它有了手腳，但它還不知道怎麼用。此時，最高級的 Context Engineering 就是撰寫 **教學手冊 (SKILL.md)**。
這不再只是提供文字，而是給予 AI：
- 工作目標。
- 嚴格的執行原則與護欄。
- 該調用哪些工具腳本的標準作業流程 (SOP)。
讓 LLM 從「好用的預測模型」真正蛻變為「專業的 AI 代理人 (Agent)」。

---

## 總結
Context Engineering 的學習曲線，是從「學習怎麼問問題」，進化到「學習怎麼結構化資訊」，最終走向「學習如何管理系統與記憶」。我們塞給 AI 的不是文字，而是它能夠理解這個世界的**「認知邊界與前提」**。
